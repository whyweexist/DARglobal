# OpenRouter model registry and fallbacks

The model catalog is refreshed from the official `GET /api/v1/models` endpoint and filtered server-side to only catalog entries with zero prompt, completion and request pricing and text I/O support. Models are cached in memory for one hour. The special `openrouter/free` router is always selectable; individual model IDs must end in `:free` and have confirmed zero pricing. If discovery fails, only the router and any previously cached free models are shown, with catalogue status visible. The UI refresh control requests a fresh catalogue.

When a user selects a model, the API validates it against the current allowlist. The LLM gateway tries that model, then `openrouter/free` when different, and additional confirmed free models, with a maximum of three candidates total. 401/403 authentication errors stop immediately. Account errors also stop early. Quotas, timeouts, output validation failures and other provider errors return distinct reason codes, with source evidence listed separately rather than presented as an answer. Explicit `INSUFFICIENT_EVIDENCE` from a model is an abstention, not a provider failure. `make check-ai` or `make local-check-ai` tests inference independently of RAG.

The selected model is reported separately from the provider-returned `model_used` when available. Free model availability is dynamic; a previously free model can disappear or become incompatible. Do not assume tool-calling support from a model slug. The live source tool is deterministic Python so model-native function calling is not required.
